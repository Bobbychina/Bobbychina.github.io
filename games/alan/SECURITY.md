# 单机本地完整性检查

`integrity.js` 是可读的 InkGuard 2.0.0 实现，`index.html` 在游戏脚本之前加载它。游戏内容以网站单机版本为基线同步至本地防护版；网站保留 `online-entry.js` 入口，本地版保留原局域网入口。这两种入口不影响单机模拟。

## 检查范围

- 游戏闭包持有独立许可对象。绑定基线、接受状态、保存、资源回执与技能回执都需要同一个对象。全局对象不暴露许可，直接调用 accept 不能洗掉修改痕迹。
- 基线只允许绑定一次。Guard 实例和全局 API 冻结，浏览器中的 InkGuard 属性不可重新赋值或配置。
- 游戏实例创建前冻结引擎原型和渲染 API，阻止常见的原型预挂载与 draw 包装。实例上的方法替换仍由每帧函数引用检查发现。
- accept 在更新状态快照前检查规则和函数完整性。帧外的生命、彩墨、冷却、伤害、速度、世界与存档内存改动继续由状态快照检查发现。
- 铜币、元宝、天赋点使用私有调用路径中的增减回执，保存前与资源账本核对。保存失败保留重试，兼容奖励留在内存和购买回滚两种调用路径。
- 保留游戏中的 InkMotion 检查：世界边界、速度、跳跃与重力、位移和模拟时钟；技能回执继续检查冷却、必杀消耗和多余回闪。

## 检测后的处理

停止本局，显示“墨迹不对劲”、检查原因和重新进入按钮。检测路径不写入、删除或重置存档，不写惩罚标记。兼容旧宿主回调时用 `detected` 标记检测结果，避免触发其 `cheat` 分支里的内存清零。旧 `runtime-tamper` 标记不再触发清档。

其他窗口改变存档时按冲突暂停，不认定作弊，不覆盖另一窗口的进度。已在检测前由修改器直接写入的外部存档不会被自动恢复；反作弊不会以恢复为名覆盖它。网站、本地 HTTP 与 file 入口各自的浏览器存储仍相互独立，本次没有迁移用户存档。

## 验证与维护

运行 `node --test tools/alan-integrity.test.cjs`，覆盖许可、禁止重绑、方法完整性、资源回执、存储失败重试、旧惩罚标记和无破坏检测。浏览器验收应使用独立上下文，验证正常战斗及改血量、伤害、彩墨、速度、冷却和实例方法后停止，逐字比较检测前后的存档。

修改 `integrity.js` 后同步到本地版。修改游戏内联调用时保留许可参数；`bind` 需要提供 save/state/rules/functions 四个读取函数。游戏逻辑仍在混淆内联脚本中，本次仅替换 Guard 模块并修改相关调用，没有整体重排游戏代码。

这是娱乐性的本地防修改器。能改网页文件、在加载前重写脚本或完全控制浏览器执行环境的人，仍然能移除检查；不保证阻挡所有修改器，也不把这些检查用于可信排名或处罚。没有扫描进程、设备指纹、上传行为或联网验证。
